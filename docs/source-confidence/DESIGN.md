# 书源置信度：怎么改才可信（双模型交叉评审 + 我的实测判定）

结论先说：**现在的置信度测不出好坏，还轻微倒挂。**

- 1698 行里 **1052 行（62%）落在 0.45–0.55** —— 分位 p20–p80 全等于 0.5，等于没信息。
- 「搜索 99% 成功但目录 87 次全失败」的源（`m.zhizihuan.com`）拿 **0.445**；而三通道都好的源拿 **0.409**。**矛盾源比好源分还高**。
- 9 个搜索成功率 ≥0.8 的好源（如 `dmshuzhai.com` 77/93）因为连败 3 次被**一刀压到 0.05**，直接进死源档。

下面是"为什么"和"怎么改"，每一步都带可复算的数字。

---

## 1. 已验证的 7 个缺陷（不是推测，代码 + 生产库都能复现）

| # | 缺陷 | 位置 | 实测后果 |
|---|---|---|---|
| 1 | `attempts == 0` 直接返回 0.5 早退 | `model/source_stat.rs:33` | **947 行**（全都有目录/正文证据）被钉死成"中性"，其中 **498 行目录成功率 <50%** |
| 2 | 通道无证据时「抄上级」`toc_rel←rel`、`cont_rel←toc_rel` | `source_stat.rs:44-52` | 没有证据被伪装成"有证据且等于搜索成功率"；1333 行目录正文都没数据 |
| 3 | `rich`（简介抓取率）在 **195/1698** 行才有数据，其余固定 0.5 | `source_stat.rs:53-57` | 白占 0.15 权重，对所有源是同一个常数 |
| 4 | 没有样本量校正 | 全函数 | `1/1` 与 `100/100` 得到同样的 `rel=1.0`，新源一次成功就冲顶 |
| 5 | 连败 3 次 = 一刀 0.05（无滞回） | `source_stat.rs:62-64` | 9 个好源（成功率 ≥0.8）被打进死源档 |
| 6 | 没有内容正确性信号 | 全函数 | `17|0|OK` 这种垃圾标题、25771 字串章，全都记成**成功** |
| 7 | 记账口径分裂：`attempts` 只记搜索，却被当成"总尝试" | `storage/mod.rs:1778` vs `:1852` | 947 行永远进不了 `attempts>=5`（死源门限）与前端 `attempts>=3`（差源门限） |

附带一条运维债：`source_stats` 有 **1087 行**是已删源的孤儿行，从不清理（同名重建的源会继承旧账）。

## 2. 双模型的分歧，和我的判定

两个模型（deepseek-v4.1-flash / hy4-preview）各写了独立方案（`proposal-a.md` / `proposal-b.md`），再互相证伪（`review-of-a.md` / `review-of-b.md`）。**两份方案的核心都被对方挑出了真错，我逐条复算后的判决：**

| 主张 | 谁说 | 我的复算 | 判定 |
|---|---|---|---|
| 用 Beta(½,½) 后验均值替代原始比例 + Wilson 区间 | A、B 一致 | 6/6 的源 Wilson 下界 **0.610**（点估计 1.0）——小样本确实被压住 | **采纳** |
| 「没有证据」要显式表达，不能伪装成 0.5 | A、B 一致 | 947 行里 **没有一条**三通道全空 ⇒ 它们不该是 0.5，而该按目录证据出分（中位 **0.306**，目录全失败的 366 行中位 **0.25**） | **采纳** |
| 通道缺失时按比例重归一权重 | A | 复算后中性带 62% → **15%** | **采纳** |
| 删除 `rich` | A | 195/1698 行有数据 | **采纳** |
| 判死与打分分离（别再用 `confidence()<=0.05` 当死源门限） | A | 一致性：现在 `0.05` 同时是"分数档"和"开关" | **采纳** |
| 但 `is_dead` 写成裸 `consec_failures>=3` + 30 天 TTL | A | 现场有 **207 行** `consec_failures>=3`，其中 **9 行搜索成功率 ≥0.8**；死源会被 `sources.retain()` 剔出搜索列表 ⇒ 不再收到新的成功记录 ⇒ 靠 30 天 TTL 才解封 | **否决**（B 的评审成立；保留 6h→24h 窗口 + 要求"样本足够"） |
| 几何池化是"一票否决"（`api.kkmh.com` 被目录通道压到 0.16） | B | 这正是想要的：搜索→目录→正文是**串联**链路，目录 0/52 的源确实交付不了 | **保留几何池化**，但加 0.02 地板 + 权重重归一，不设"硬 0 乘子" |

| `lcb`/`ucb` 修小样本，冷启动用 `ucb` | B | `ucb` 让**无证据源 0.789 冲队首**（高于 p90=0.709）；且 B 自己算的 `0.445−0.602` 写成 **+0.157**，符号错 | **否决** |
| 只读现成数据、不新增网络请求 | A、B 一致 | 一致 | **采纳** |

## 3. 定稿模型（第一步就能落，只改一个文件 + 两处调用）

不改表结构时的打分：

```rust
// backend/src/model/source_stat.rs —— 替换 confidence()
const W_SEARCH: f64 = 0.45;
const W_TOC: f64 = 0.35;
const W_CONTENT: f64 = 0.20;
const POOL_FLOOR: f64 = 0.02;

/// 每条通道：Beta(½,½) 后验均值 —— 1/1 不会拿满分，0/3 也不会是 0
fn channel(ok: i64, n: i64) -> Option<f64> {
    if n <= 0 { return None; }
    Some((ok as f64 + 0.5) / (n as f64 + 1.0))
}

impl SourceStat {
    /// 该源下一次被调用时能交付可用内容的概率；None = 三条通道全都没证据
    pub fn confidence(&self) -> Option<f64> {
        let chs = [
            (W_SEARCH, channel(self.successes, self.attempts)),
            (W_TOC, channel(self.toc_successes, self.toc_attempts)),
            (W_CONTENT, channel(self.content_successes, self.content_attempts)),
        ];
        let live: Vec<(f64, f64)> = chs.into_iter().filter_map(|(w, v)| v.map(|v| (w, v))).collect();
        if live.is_empty() { return None; }
        let wsum: f64 = live.iter().map(|(w, _)| w).sum();
        // 串联链路：任一环失效即不可用 → 几何池化（有地板，不会归零）
        let mut p = (live.iter().map(|(w, v)| w * v.max(POOL_FLOOR).ln()).sum::<f64>() / wsum).exp();
        // 慢是"慢"，不是"坏"：只有超过 10s 才温和扣，最多扣到 0.7（旧版整体压到 0.3 倍）
        let avg = self.lat_sum_ms as f64 / self.attempts.max(1) as f64;
        if avg > 10_000.0 { p *= (1.0 - (avg - 10_000.0) / 60_000.0 * 0.3).max(0.7); }
        // 连败改成滞回：第 3 次起每次减半，最多 1/8；不再"一刀 0.05"
        if self.consec_failures >= 3 { p *= 0.5_f64.powi((self.consec_failures - 2).min(3) as i32); }
        Some(p.clamp(0.0, 1.0))
    }

    /// 判死与打分分开：要求"样本足够 + 成功率确实低"，不再借用 0.05 分数档
    pub fn is_dead(&self, now_ms: i64) -> bool {
        let decisive = (self.attempts - self.timeouts).max(0);
        decisive >= 5
            && now_ms - self.last_failure_at <= 24 * 3_600_000
            && (self.successes as f64 / decisive as f64) < 0.2
    }
}
```

**为什么这样能变可信**（我按这套公式回算全部 1698 行）：

| 指标 | 现在 | 改后 |
|---|---|---|
| 中性带（0.4–0.6）占比 | **62%**（1052 行） | **15%**（252 行） |
| 矛盾源（搜索好/目录 0）中位分 | 0.445 | **0.231** |
| 三通道都好源中位分 | 0.409 | **0.752** |
| 两者差值 | **−0.036（倒挂）** | **+0.521** |
| 9 个"成功率 ≥0.8 却被判死"的源 | 一律 0.05 | 0.073 ~ 0.402（回到中下游，仍可被搜到） |
| 947 行 TOC-only 源 | 一律 0.5 | 中位 0.306，目录全失败的 366 行中位 0.25 |

## 4. 三步落地（每步都能单独上线、单独回滚）

**第一步（纯计算，无迁移，风险最低）**：上面的 `confidence() -> Option<f64>` + `is_dead()`。
- 调用点要同步改签名：`router.rs:2942`、`:4877`、`:9430`（`unwrap_or(0.5)` → `unwrap_or(UNKNOWN)` 显式占位）；`router.rs:9911` 改调 `is_dead`；`SourcesPage.tsx:184/197` 的 `attempts` 门限换成"有效样本"（三通道 n 之和）。
- 排序键用 **Wilson 下界**（`conf.lo`）而不是点估计：5/5 的源从 1.0 降到 0.566，新源不再冲顶。
- 门禁：`source_stat.rs` 现有 5 个测试要改期望值（`0.05` 档消失）；新增 4 条（全空→None、只有目录证据、6/6 的 lo、连败滞回）。

**第二步（一个迁移，两个写点）**：`ALTER TABLE source_stats ADD COLUMN toc_updated_at INTEGER NOT NULL DEFAULT 0`（content 同理）。拿到分通道时间戳后才能做**时间衰减**（半衰期 30–60 天）——现在全表只有一个 `updated_at`，8 周的旧成功和今天的成功等权。回填时**不能**用 `updated_at` 顶替（944 行会被锚到搜索时间，等于没做），一律留 0 表示"锚点未知，先不衰减"。

**第三步（内容正确性，真正的新信号）**：在 `router.rs:4812/:4850` 成功/失败**两处**都记账，判"这段正文可信吗"：
- 标题必须像章节名（前端 `looksLikeChapterTitle` 已有同样口径，后端需要一份）；
- 单章字数落在全网中位数的 0.3–3 倍内（实测干净章 ≈3215 字，串章源 21635–304567 字）；
- 命中则 `sane_hits++`，否则 `sane_attempts++`（失败分支也记）。
- 不新增任何网络请求，只在已有解析结果上多判一次。

**不做**：抓第二个源做交叉比对（一次请求变两次，收益不抵成本）；给 `d_*` 加衰减快照列（读改写 + 并发重试，换不来精度）。

## 5. 怎么证明"更可信"（可复算的验收口径）

上线前后各跑一次（只读生产库）：

1. 中性带占比 `< 20%`（现 62%）；
2. 矛盾源中位分 **低于** 全好源至少 0.2（现是倒挂）；
3. 搜索成功率 ≥0.8 的源里，被压到 0.05 的个数 = **0**（现 9）；
4. `SourcesPage` 的「差源」清单里，人眼抽查 10 个至少有 7 个确实是坏的（现在是按 `confidence<0.4` 圈，混着大量目录全废但搜索正常的源）。

第一步不需要动表、不需要动前端结构，我可以直接做。
